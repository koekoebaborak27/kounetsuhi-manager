## 画面の振り分け

画面を開くたびに、ログイン状態と世帯への所属を確かめ、次の表のとおりに移すこと。

| 状態 | 開こうとした画面 | 移す先 |
|---|---|---|
| ログインしていない | S01 以外 | S01 ログイン |
| ログイン済み・世帯に未所属 | S02 以外 | S02 初回設定 |
| ログイン済み・世帯に所属済み | S01・S02 | S03 ホーム |

- ログインした直後は、上の表に従って S02 または S03 を表示すること。
- データの取得・更新はすべて、ログイン中の人が所属する世帯に絞り込むこと。他の世帯の検針票・契約の ID を URL に入れて開いたときは、存在しないものとして扱い、「データが見つかりません。」と表示すること。

## タブ

- 「ホーム・記録・グラフ・設定」の 4 つのタブを置くこと。画面の幅が 1024px 未満のときは画面の下部に、1024px 以上のときは画面の左側に縦に並べること。
- S01・S02 ではタブを表示しないこと。
- S04 検針票の入力と S08 契約では、表示中のタブを、開く元になった画面のタブ（S04 はホームまたは記録、S08 は設定）とすること。
- S04 で入力内容を変更した後にタブで別の画面へ移ろうとしたときは、「入力内容が失われます。移動しますか？」と確認し、「移動する」を押したときだけ移ること。「キャンセル」を押したら S04 に留まること。
- S04 で入力内容を変更した後に、ページを再読み込みする・ブラウザのタブを閉じるときは、ブラウザが用意している確認を出すこと（文言とボタンはブラウザが決めるため、上の確認とは異なる）。ブラウザの「戻る」は確認の対象外とする。

## 表示の形式

| 対象 | 形式 | 例 |
|---|---|---|
| 金額 | 3 桁ごとにカンマを入れ、後ろに「円」 | 12,640 円 |
| 負の金額 | 先頭に「−」 | −58 円 |
| 日付 | `YYYY/MM/DD` | 2026/07/13 |
| 使用月 | `YYYY 年 M 月分`。水道は前月を含めて `M-M 月分` | 2026 年 8 月分、7-8 月分 |
| 請求月 | `YYYY 年 M 月` | 2026 年 9 月 |
| 増減率 | 小数 1 桁に四捨五入し、増は「+」、減は「−」を付ける | +15.1%、−5.5% |
| 使用量 | 小数 1 桁と単位（電気 kWh、ガス・水道 ㎥） | 19.4 ㎥ |

- 日付・年月は日本時間で表示すること。
- 水道の使用月が 1 月のときは、前月を前年 12 月として「12-1 月分」と表示すること。年を付けて表示する場面（S04 の使用月など）では、両方の年を書いて「2026年12月-2027年1月分」と表示すること。

## 共通のエラー表示

| 場面 | 表示する文言 |
|---|---|
| 保存・発行・参加などの更新が、通信やサーバーの問題で失敗したとき | 保存できませんでした。通信状態を確認して、もう一度お試しください。 |
| 画面の表示に必要なデータを読み込めなかったとき | 読み込めませんでした。通信状態を確認して、画面を再読み込みしてください。 |
| 世帯のデータに無い ID を開いたとき | データが見つかりません。 |

- 更新に失敗したときは、入力内容を消さずにその画面に留まること。

## データの持ち方

- 各テーブルの ID は文字列とし、アプリで作るテーブルは cuid を使うこと。
- 使用月・請求月は「その月の 1 日」、使用期間・契約の開始日と終了日は時刻を持たない日付（PostgreSQL の `date`）として保存すること。
- 金額は円単位の整数とすること。
- 作成日時・更新日時は時刻つき（UTC）で保存すること。

## 外部からの読み取りの防止

- Supabase の Data API を無効にし、DB へはアプリ（Prisma）からだけ接続すること。

## DB の一時停止の防止

- Vercel Cron で 1 日 1 回、アプリの専用の URL を呼び出し、DB へ軽い問い合わせ（`SELECT 1`）を送ること。
- この URL は Vercel Cron が付ける秘密の値を確かめ、それ以外からの呼び出しは拒否すること。

## グラフのライブラリ

- グラフは Recharts で描くこと。
