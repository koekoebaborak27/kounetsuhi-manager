## 目的

電気・ガス・水道の請求額と使用量を検針票 1 枚ごとに記録し、次のことにすぐ答えられるようにすること。

- 今月の光熱費は高いのか（前回・前年同月と比べて）
- 季節によってどう変わるのか
- 契約を見直すときの判断材料（使用量と請求額の推移、請求額の内訳）

## 利用者と利用端末

- 利用者は 1 世帯の家族（3 人を想定）とすること。全員が同じ操作をできること。
- 主な利用端末は Android スマートフォンの Chrome とし、ホーム画面に追加して使えること（PWA）。
- 家庭の PC のブラウザからも同じ画面を使えること。
- iPhone（Safari）での動作は保証しない。

## 前提と制約

| 項目 | 内容 |
|---|---|
| 開発期間 | 1 週間 |
| 費用 | 無料プランの範囲だけで運用すること |
| 公開範囲 | インターネットに公開し、ログインした家族だけが使えること |
| 技術 | TypeScript / Next.js、Prisma、PostgreSQL（Supabase の無料プラン）、Better Auth、Vercel（Hobby プラン） |
| 外部 AI | アプリの中で AI の API を使わないこと |
| DB | 開発用と本番用を分けず、1 つの DB を使うこと |

## 用語

| 用語 | 意味 |
|---|---|
| 種別 | 電気・ガス（都市ガス）・水道の 3 つ |
| 検針票 | 請求 1 回分の記録。アプリでは 1 枚を 1 件として扱う |
| 使用月 | 検針票に書かれた「○月分」の年月（多くは検針日のある月）。**記録・集計・比較はすべて使用月を基準にする**。水道のように 2 か月分をまとめた検針票は、後ろの月を使用月とし、「5-6 月分」のように表示する |
| 請求月 | 検針票に書かれた請求の年月。任意の記録項目で、集計・比較には使わない |
| 使用期間 | 検針票に書かれた使用の開始日と終了日 |
| 契約 | 種別・会社・プランの組み合わせと、その契約期間 |
| 内訳項目 | 基本料金・電力量料金などの請求額の内訳。契約ごとに使う項目を選んでおく |
| 1 日あたりの金額 | 請求額 ÷ 使用期間の日数 |
| 招待コード | 家族を世帯に招くためのコード。メンバーが発行し、1 回だけ使える |

## データに関する共通ルール

- **データを削除する機能は作らないこと**（世帯から退出した人の所属の情報は除く）。誤りは編集で直す。どうしても消す必要があるときは、Supabase の管理画面から手作業で消す。
- 使用月・請求月は「その月の 1 日」の日付で持つこと。使用月・請求月・使用期間は時刻を持たない日付として保存し、サーバー（UTC）と日本時間の差で日付がずれないようにすること。
- 金額は円単位の整数とすること。
- 1 日あたりの金額・前回比・前年同月比・内訳合計と請求額の差は保存せず、表示するときに計算すること。
- 誰が入力・更新したかは記録しないこと。

## 権限

- ログインできるのは、Google Cloud の OAuth 同意画面に「テストユーザー」として登録した Google アカウントだけとすること。
- データを見たり変えたりできるのは、自分が所属する世帯のデータだけとすること。
- 世帯のメンバーは全員同じ操作ができること（閲覧・作成・編集・招待）。ただし、世帯から退出できるのは一般のメンバーだけとする。

## 非機能要件

| 分類 | 要件 |
|---|---|
| セキュリティ | Google 以外のログイン方法を無効にすること。すべてのデータ取得・更新で、ログイン中の人が所属する世帯に絞り込むこと。Supabase の Data API から外部にテーブルを読まれないよう、全テーブルで RLS を有効にして許可ルールを作らないか、Data API を無効にすること |
| 可用性 | Supabase の無料プランは、しばらく使われないとプロジェクトが一時停止される。これを避けるため、Vercel Cron で 1 日 1 回 DB へ軽い問い合わせを送ること |
| 性能 | データは年に 40 件程度なので、特別な性能要件は設けない。スマートフォンで各画面が待たされずに表示されること |
| PWA | ホーム画面に追加できること（アイコン・名前）。オフラインでの動作と通知は対応しない |
| 見た目 | スマートフォンの画面幅を優先し、文字は大きめにすること。ダークモードは対応しない。ログイン画面の背景画像はデザインを決める工程で決める |

## 運用

- バックアップ機能は作らないこと。必要に応じて、Supabase の管理画面からテーブルを CSV で書き出す。
- 開発用と本番用で DB を分けないため、家族で使い始める前に開発中のテストデータを消すこと。
- DB を作り直すコマンド（`prisma migrate reset` 等）は実行しないこと。

## 対象外とすること

- オフラインでの入力・閲覧
- 検針票の写真から文字を読み取る機能
- 他社プランとの料金試算
- 入力忘れの通知
- CSV の取り込み・書き出し、バックアップ機能
- 日割りでの按分
- 内訳の推移グラフ
- 複数世帯への所属、世帯をまたいだ比較
- 同じ人数の世帯の平均（総務省「家計調査」）との比較
- 実質単価（請求額 ÷ 使用量）の推移グラフ
- 灯油・プロパンガス
- データの削除
- 入力者の記録
- ダークモード
