# 03. Google ログインの本番設定 — 8-3 で実施

Google Cloud の OAuth クライアントと同意画面を本番用に整える。開発用の手順は [`Googleログインの準備.md`](../../development/Googleログインの準備.md)。画面の名前は 2026-09 時点のもの（Google Cloud のコンソールは日本語表示）。

## 事前に必要なもの

- 本番の URL（`https://<プロジェクト名>.vercel.app`）。**Vercel のプロジェクトを先に作って URL を確定してから行う**（[04 の 1](infra_design_04_Vercel.md#1-プロジェクトを作って-url-を確定する8-3-の前に行う)）。
- 家族の Google アカウントのメールアドレス。

## 1. 使うクライアントとプロジェクトを決める

- **決めたこと（2026-09-30）:** Google Cloud のプロジェクトは開発用と同じものを使い、OAuth クライアントも**開発用のものに本番の URL を足す**（別のクライアントは作らない）。
- 理由: 同意画面（Google Auth Platform）とテストユーザーをそのまま使える。クライアントが 1 つで済む。
- 注意（別のクライアントを作る案との違い）: 開発用と本番で**クライアントシークレットが同じ**になる。片方で漏れたら、もう片方も作り直しになる。家族向けの小さなアプリなので許容した。分けたくなったら、本番用のクライアントを新しく作り、リダイレクト URI を付け替える。
- `BETTER_AUTH_SECRET` は、クライアントを共有しても**本番用に別の値**を作る（[01](infra_design_01_事前準備.md)）。

## 2. 同意画面（Google Auth Platform）を確かめる

URL が要らない作業。開発用の設定をそのまま使えるかを確かめるだけで、変更はしない。

1. [Google Cloud コンソール](https://console.cloud.google.com/) で、開発用のプロジェクトを選ぶ。
2. 左メニューの「Google Auth Platform」を開く。
3. 「**対象**」を開き、次の 2 点を確かめる。
   - 公開ステータスが「**テスト**」のままであること（「本番環境にする」は押さない）。
   - 「テストユーザー」に、家族全員の Google アカウントが入っていること。入っていない人は、Google の画面でログインが止まる（アプリ側では判定しない）。足す場合は「Add users」から追加する。
4. 「**データアクセス**」を開き、スコープが**何も追加されていない**こと（「非機密のスコープ」「機密性の高いスコープ」「制限付きのスコープ」の 3 つの表がすべて空）を確かめる。アプリが求める `openid`・`email`・`profile` は基本のスコープで、この画面に載せなくてもログインで使える。「スコープを追加または削除」は押さない。

> 確認結果（2026-09-30）: 公開ステータスは「テスト」、家族はテストユーザーに登録済み、スコープは追加なし。

## 3. 承認済みの URI を登録する

1. 左メニューの「Google Auth Platform」→「**クライアント**」を開き、開発用のクライアント名を押して編集画面を開く。
2. 「**承認済みの JavaScript 生成元**」の「**URI を追加**」を押し、次を入れる。
   - `https://<プロジェクト名>.vercel.app`
   - 末尾のスラッシュは付けない。`http` ではなく `https`。
3. 「**承認済みのリダイレクト URI**」の「**URI を追加**」を押し、次を入れる。
   - `https://<プロジェクト名>.vercel.app/api/auth/callback/google`
4. 開発用の `http://localhost:3000` 系の 2 件は**消さずに残す**（手元での開発に使う）。
5. 画面の一番下の「**保存**」を押す。反映に数分かかることがある。

> 実施結果（2026-09-30）: 上の 2 件を追加して保存した。

## 4. クライアント ID とシークレットの扱い

- 新しく作らないので、値は開発用の `.env` に入っているものと同じ。
- **控えておく場所:** パスワード管理ツール（`.env` を失くしたときのため）。チャット・コード・ドキュメントには書かない。
- 04 で、本人が Vercel の環境変数（Production）へ入れる。クライアントの編集画面はシークレットが写ることがあるので、スクリーンショットを撮るときは写さない。

## Better Auth 側で本番 URL を指定する箇所

- コードに URL は書かない。**環境変数 `BETTER_AUTH_URL`** に本番の URL（`https://<プロジェクト名>.vercel.app`）を入れる。Better Auth はこの値から、Google へ渡すリダイレクト先（`<BETTER_AUTH_URL>/api/auth/callback/google`）を作る。
- Google の承認済みリダイレクト URI と、`BETTER_AUTH_URL` から作られる URL が**1 文字でも違うと**ログインが失敗する（`redirect_uri_mismatch`）。末尾のスラッシュ・`http` と `https` の違いに注意する。
