# 05. 動作確認と運用 — 8-5・8-6 で実施（A は 2026-09-30 完了、B は 8-6 で書く）

本番の通し確認（8-5）と、運用の取り決め（8-6）。**A は実際に操作して書いた。B は章立てまで。**

## A. 本番の動作確認（8-5）

前提: 02（DB）・03（Google）・04（Vercel）が完了していること。PWA の manifest とアイコンは 8-B で実装済み。

### 方針

- **本番のデータは、そのまま運用に移れる実データで確認する。** 世帯名も実際に使う名前で作る。理由は、1 つの Google アカウントが所属できる世帯は 1 つだけで、試しの世帯を作るとそのまま本番の世帯になるため。世帯名は設定画面（S07）から後で変えられる。
- 検針票は実際の 1 枚だけ登録する。契約と検針票は画面から削除もできる（検針票がある契約は、先に検針票を消さないと削除できない）。
- 操作は人が本番の URL で行い、エージェントは 1 手順ずつ案内した。実際の値（URL・メールアドレス・世帯名・金額・招待コード）はここに書かない。スクショを残すときは、写る値を隠す。
- 本番に対しては、`pnpm db:reset` などの DB を作り直す・直接書き換える操作を行わない。

### 手順と結果

`<本番の URL>` は Vercel の本番の URL。

| # | 手順（画面と押すボタン） | 見るところ | 結果 |
| --- | --- | --- | --- |
| 1 | PC のブラウザで `<本番の URL>` を開く → 「Google でログイン」→ テストユーザーの Google アカウントを選ぶ。同意画面が「テスト」のため「このアプリは Google で確認されていません」と出たら、「詳細」→ 「移動（安全ではないページ）」→ 権限の確認で「続行」 | ログイン後に初回設定画面（S02）が出る | 成功 |

### 実施しなかったこと

| 項目 | 理由 |
| --- | --- |
| 2 人目の家族が招待コードで参加する | 確認に使える 2 つ目のテストユーザーのアカウントを用意しなかったため。実際に家族が使い始めるときに、招待コードの発行（S07）と参加を試す |
| テストユーザー以外の Google アカウントが止まること | 確認に使えるテストユーザー以外のアカウントを用意しなかったため。同意画面が「テスト」で、テストユーザーだけが許可される仕組みは Google 側の設定（[03](infra_design_03_Googleログイン.md)）で、アプリ側では確かめていない |
| エラー時の Vercel の Logs での原因確認 | 確認中にエラーが出なかったため、実際には使わなかった。見方は 8-6 の障害時の確認順に書く |

## B. 運用の取り決め（8-6）

### 章立て

1. バックアップ: 機能は作らない。Supabase の管理画面からテーブルを CSV で書き出す手順と、書き出す頻度の目安
2. 無料プランの制限: Supabase の一時停止の条件・再開の方法、Cron が止まったときの気づき方。Vercel Hobby の制限（非商用・Cron の回数・転送量）
3. スキーマを変えるときの流れ: [00 の 6](infra_design_00_概要と全体構成.md#6-マイグレーションの流し方の方針) の再掲と、確認チェックリスト
4. 障害時の連絡と戻し方: 画面が開かない・ログインできない・DB に届かない、それぞれの確認順と戻し方（Vercel のロールバック、Supabase の再開）
5. シークレットの入れ替え手順: `BETTER_AUTH_SECRET`・Google のクライアントシークレット・DB のパスワードを変えるときの順序（変えたあとの再デプロイを含む）
6. [`README.md`](../../../README.md) の「本番デプロイ」を、実際の手順に合わせて直す
