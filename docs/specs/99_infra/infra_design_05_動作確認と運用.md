# 05. 動作確認と運用 — 8-5・8-6 で実施

本番の通し確認（8-5）と、運用の取り決め（8-6）。**この文書は章立てと確認項目まで。** 詳細は各タスクで、実際に操作しながら書き足す。

## A. 本番の動作確認（8-5）

前提: 02（DB）・03（Google）・04（Vercel）が完了していること。

### 章立て

1. ログイン: 本番の URL で「Google でログイン」を押し、テストユーザーのアカウントでログインできる
2. テストユーザー以外の Google アカウントでは、Google の画面で止まる
3. 世帯の作成と招待: 初回設定（S02）で世帯を作り、招待コードでもう 1 人が参加できる
4. 契約と検針票の登録: 契約（S08）・検針票（S04）を登録し、記録（S05）に出る
5. ホームとグラフ: ホーム（S03）・グラフ（S06）に反映される
6. スマホ（Android の Chrome）: 各画面の表示、ホーム画面への追加（PWA）と、追加したアイコンからの起動。**PWA の manifest とアイコンの実装後に行う**（[00 の 4](infra_design_00_概要と全体構成.md#4-現時点でコードに無いもの本番構築の前に別タスクで実装する)）
7. 確認で作った試しのデータの扱いを決める（削除機能が無いため、本番に残ってよい名前・内容で作る）

### 確認項目（完了の条件）

- [ ] 上の 1〜6 がすべて成功した（結果は履歴に「何を・どう確認したか」を残す）
- [ ] エラーが出た場合、Vercel のログで原因を確認できる

## B. 運用の取り決め（8-6）

### 章立て

1. バックアップ: 機能は作らない。Supabase の管理画面からテーブルを CSV で書き出す手順と、書き出す頻度の目安
2. 無料プランの制限: Supabase の一時停止の条件・再開の方法、Cron が止まったときの気づき方。Vercel Hobby の制限（非商用・Cron の回数・転送量）
3. スキーマを変えるときの流れ: [00 の 6](infra_design_00_概要と全体構成.md#6-マイグレーションの流し方の方針) の再掲と、確認チェックリスト
4. 障害時の連絡と戻し方: 画面が開かない・ログインできない・DB に届かない、それぞれの確認順と戻し方（Vercel のロールバック、Supabase の再開）
5. シークレットの入れ替え手順: `BETTER_AUTH_SECRET`・Google のクライアントシークレット・DB のパスワードを変えるときの順序（変えたあとの再デプロイを含む）
6. [`README.md`](../../../README.md) の「本番デプロイ」を、実際の手順に合わせて直す
