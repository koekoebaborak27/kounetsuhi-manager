# 02. Supabase（本番 DB）— 8-2 で実施

本番の PostgreSQL を作り、マイグレーションを流す。**この文書は章立てと確認項目まで。** 画面のボタン名までの手順は、8-2 で実際に操作しながら書き足す。方針は [00](infra_design_00_概要と全体構成.md)、環境変数は [01](infra_design_01_事前準備.md)。

## 章立て

1. プロジェクトを作る
   - 組織・プロジェクト名・リージョン（東京 `ap-northeast-1`）・DB のパスワード（自動生成して保管）・プラン（無料）
   - 決めた設定値を、この節に残す（値そのものではなく「何を選んだか」）
2. 接続文字列を控える
   - Transaction モード（6543）と Session モード（5432）の 2 種類を、管理画面の接続情報から取得する
   - 保管先はパスワード管理ツール。ファイル・チャット・履歴に残さない
3. マイグレーションを流す
   - 手元のシェルにだけ `DATABASE_URL`（Session モード）を設定し、`pnpm exec prisma migrate deploy` を実行する
   - 終わったらシェルの変数を消す
4. テーブルができたことを確かめる
   - 管理画面のテーブル表示で、マイグレーションのテーブル（`_prisma_migrations` を含む）が並んでいることを確認する
5. 一時停止の設定を確認する
   - 一時停止の条件と、再開の方法（管理画面の操作）を確認して書く

## 確認項目（完了の条件）

- [ ] リージョンが東京になっている
- [ ] `migrate deploy` が成功し、`prisma/migrations` の件数と `_prisma_migrations` の行数が一致する
- [ ] 接続文字列とパスワードがコード・ドキュメント・チャットに残っていない
- [ ] `psql` などで本番のテーブルを直接書き換えていない（スキーマを変える手段は migration のみ）

## 注意

- 本番に対して `migrate dev` / `migrate reset` / `db push` / seed は実行しない（[`prisma_operations.md`](../../prisma_operations.md) の 3-3）。
- アプリは Supabase の認証・Storage・API を使わない。DB だけを使う。
- 失敗したときの戻し方は [00 の 6](infra_design_00_概要と全体構成.md#6-マイグレーションの流し方の方針)。
