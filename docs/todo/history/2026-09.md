## 2026-09-25 要件の壁打ちと要件定義書の作成

AI と壁打ちし、結果を [`docs/specs/01_requirements/`](../../specs/01_requirements/README.md) に書き起こし、ユーザーのレビューを経て確定した。

### 当初案から変えたこと

| 当初案 | 決定 | 理由 |
|---|---|---|
| PC でローカル起動（localhost）、SQLite、非公開 | Vercel + Supabase（PostgreSQL）で公開し、Google ログインで家族に限定 | スマホから PWA として使いたい。PWA は HTTPS が必須で、家庭内 LAN だけで HTTPS にするのは手間が大きい |
| Supabase Auth または RLS で守る | Better Auth + Prisma。世帯での絞り込みはアプリのコードで行い、RLS は Data API の蓋としてだけ使う | Prisma のソースを自分で理解したい。扱うデータの機密性は高くない |
| 許可メールアドレスの一覧 | Google 側はテストユーザー登録、アプリ側は世帯（家族グループ）への所属で二重に制限 | 独自ドメインが無くても、同意画面を「テスト」状態にすればテストユーザーしかログインできない |
| CSV 取り込み・書き出し、自動バックアップ | 作らない。必要なら Supabase の管理画面から手動で書き出す | 年 40 件程度のデータで、機能に見合わない |
| 削除機能 | 作らない。誤りは編集で直す | 請求月と契約の組み合わせを重複不可にしたため、二重登録が起きない |
| 開発用と本番用の DB を分ける | 分けない | 個人利用のため。代わりに利用開始前にテストデータを消す |
| 内訳の項目名を自由入力 | 契約の登録時に候補から選択。毎月は金額だけ入力 | 自由入力は毎回手間がかかる |
| 集計・比較の基準は請求月 | 使用月（検針票の「○月分」）。請求月は任意の記録項目 | 6 月の使用分が 9 月に請求されることがあり、請求月ではどの月に多く使ったかが分からない |
| 開発期間 約 1 か月 | 1 週間 | ユーザーの予定変更。機能の絞り込みはレビューで決める |
| 画面名「履歴」 | 「記録」。請求月を切り替えて作成・編集する画面 | 作成もする画面なので「履歴」は合わない |

### 不採用にした案

- 年ごとの種別の割合を示す横棒（年間タブ）：意味が薄いため。
- 推移グラフで水道を 2 か月にならして積み上げる案：請求額とそのまま一致するほうを優先した。代わりに注記を入れる。
- 内訳の推移グラフ、入力者の記録、ダークモード：必要性が低いため。
- 実質単価（請求額 ÷ 使用量）の推移グラフ（単価タブ）：開発期間を 1 週間にしたため削った。契約切替の月に縦線を入れて効果を見る案だった。
- 世帯平均（総務省「家計調査」の世帯人員別・月別の電気代・ガス代・上下水道料との比較）：開発期間を 1 週間にしたため削った。見積もりは 3〜5 時間（e-Stat の表探しと整形に時間がかかる）。復活させる場合の検討結果は次のとおり。
  - seed で年・月・世帯人数・種別ごとの平均額を持ち、年 1 回手作業で更新する。世帯に「世帯人数」（ログインしない家族も含む）を持たせる。
  - 水道は検針票 1 枚が 2 か月分なので、使用月とその前月の平均の合計と比べる。
  - 注記：金額のみ・ガスは都市ガスとプロパンの合算・地域差なし・公表が 1〜2 か月遅れ・支払月基準のため使用月と 1 か月ずれる。

## 2026-09-25 画面イメージのHTMLひな形でレイアウトをすり合わせ

AI が主要画面（S01〜S08。グラフは 3 タブ）の HTML ひな形を [`docs/mockups/画面イメージ.html`](../../mockups/画面イメージ.html) に作り、スマホ版（幅 360px）と PC 版（幅 1000px）でレイアウトを確定した。デザインの作り込みは、検討者が画像を用意してから行う。ログイン画面の背景画像とロゴは検討者が差し替えた。

迷った箇所は画面の余白に「※要確認」と書き、1 問ずつ質問して決めた。決まった内容は要件定義書（[`docs/specs/01_requirements/`](../../specs/01_requirements/README.md)）へ反映した。

### 要件から変えたこと

| 当初の要件 | 決定 | 理由 |
|---|---|---|
| 家族のメールアドレスを登録して招待し、初回ログイン時に自動で参加させる | 招待コードを発行してコピーで渡し、初回設定で入力して参加する。コードは 1 回限り・期限つき（7 日を想定）。取り消しは作らない | 検討者の希望 |
| 画面の下部に 4 つのタブ | 画面幅 1024px 以上（PC）は左側の縦メニューにする | 横長の画面では左メニューが一般的。タブレットの縦持ちはスマホ版にする |
| S08 契約の登録 | 画面名は登録・編集とも「契約」 | 検討者の希望 |
| 検針票の入力に戻る操作の定めなし | 保存の横に「キャンセル」。入力中に別の画面へ移るときは確認を出す | 入力内容を誤って失わないため |
| 使用期間の終了日は初期値なし | 開始日の 1 か月後の前日（水道は 2 か月後の前日） | 入力の手間を減らす |

ほかに、ホームの増減の色（増＝赤、減＝青）、今年の合計の強調、年比較の年数（過去 2 年）、年間タブの前年比（前年の同じ期間と比較）と月平均（記録のある月数で割る）を決めた。

### 不採用にした案

- 招待で自動参加したことを知らせる表示：不要と判断した。その後、招待コード方式にしたため自動参加自体が無くなった。
- 年比較で水道の横軸を 1〜12 月にする案：一度はこちらを選んだが、要件の「水道だけのグラフは 2 か月単位」に合わせて戻した。
- PC 版で記録画面の右に検針票の入力を並べる案：入力欄が狭くなり、作りも複雑になるため、スマホ版と同じく別の画面へ移る形にした。
- 検討者が画像を用意してデザインを作り込む案：ひな形のデザインで十分と検討者が判断したため行わない。画面イメージ検討はこれで完了とした。

## 2026-09-25 GitHubリポジトリの作成と初回push

`git init` し、GitHub に [koekoebaborak27/kounetsuhi-manager](https://github.com/koekoebaborak27/kounetsuhi-manager)（public）を作って `main` へ初回 push した。CI は成功した。

- push の前に、ローカルで CI と同じ確認（`pnpm install --frozen-lockfile` → `pnpm lint` → `pnpm format:check` → `pnpm typecheck` → `pnpm test`）を行い、すべて通ることを確かめた。
- 画面イメージの HTML（`docs/mockups/`）は Prettier の書式で整えておらず、整形チェックで CI が落ちるため、`.prettierignore` に `docs/mockups/` を足した。見本のファイルなので整形は不要と判断した（`pnpm format` で整形する案は不採用）。
- `main` のブランチ保護は設定せず、運用ルール（コードの変更は feature ブランチ → PR）で守ることにした。public なので設定はできるが、個人開発のため。[`AGENTS.md`](../../../AGENTS.md) と [`gitの操作ルール.md`](../../development/gitの操作ルール.md) の記述もこれに合わせた。
