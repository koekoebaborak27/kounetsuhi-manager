- 設計書に無く、こちらで決めたこと
  - 同時参加: トランザクションの中で「未使用かつ期限内」を条件に招待コードを更新し（`updateMany`）、更新件数が 0 なら参加させずに使用済みの文言を出す。PostgreSQL は同じ行の更新を 1 つずつ行い、後の更新は先の確定後の値で条件を見直すため、先の 1 人だけが通る。同じ人が別のタブで同時に参加した場合は、Membership の `userId` の一意の決まりで 2 つ目が失敗し、トランザクションごと取り消される（共通のエラー文言になる）。
  - 招待コードの文言の優先順は、空 → 形の誤り・DB に無い → 使用済み → 期限切れ。使用済みかつ期限切れなら「使用済み」を出す。期限の時刻ちょうどは期限切れとして扱う。
  - 「すでに所属している」の確認は、入力チェックより先に行う（入力が空でも、所属していればそのまま S03 へ移す）。
  - コードの重なりは、発行の前に DB に同じコードが無いか確かめて作り直す（最大 5 回。上限に達したら更新失敗の共通の文言）。乱数は `node:crypto` の `randomInt`。
  - エラーの出し方: 入力チェックと招待コードの照合の失敗は入力欄の下、それ以外（通信やサーバーの問題）はトースト。世帯名の保存後のトーストは出さない（設計書は「表示に戻す」だけのため）。
  - 発行・世帯名の保存の後は `revalidatePath("/settings")` で画面のデータを読み直し、一覧と世帯名を最新にする。
  - 日付は日本時間の「YYYY/MM/DD」にする関数を `src/shared/format/date.ts` に置いた（5-5 以降の画面でも使うため）。
  - タブのある画面で読み込みに失敗したときに共通の文言を出す `src/app/(main)/error.tsx` を足した。
  - S07 の「世帯から退出」「ログアウト」は、PC では 2 列の下に並べた（設計書のとおり。画面イメージではログアウトが左の列の中にあった）。
- 確認: `pnpm lint` / `format:check` / `typecheck` / `test`（114 件）/ `build` が成功。ログインが要る画面のため、ブラウザでの確認（作成・招待・参加・退出・ログアウト）はユーザーが行う。
