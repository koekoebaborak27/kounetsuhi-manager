## 2026-09-28 Better AuthでGoogleログインと画面の振り分けを作成

TODO の 5-4 の 2 つ目の PR（②認証）。① は PR #5 でマージ済み。

- 入れたもの: `better-auth` 1.7.6（npm の latest。Next.js 14〜16・Prisma 5〜7・React 18〜19 に対応）。スキーマを作る CLI は `auth` パッケージ（`pnpm dlx auth@1.7.6 generate`）。
- テーブル: CLI が出した Session・Account・Verification を `schema.prisma` に手で取り込んだ。ユーザーに確認して、CLI が付ける `@@map("user")` などのテーブル名の変更は付けず、日時は既存のテーブルと同じ `@db.Timestamptz(3)` にそろえた。Better Auth は `prisma.user` のようにモデル名で読み書きするので、`@@map` が無くても動く。論理名と説明はユーザーに確認して決め、マイグレーション `add_better_auth_tables`（`--create-only` で作って `COMMENT ON` を 30 件足した）と [`01_データベース.md`](../../specs/02_basic-design/01_認証と世帯/01_データベース.md) に書いた。
- 設定（`src/modules/auth/auth.ts`）: Google ログインだけを有効にし、求める範囲を `openid`・`email`・`profile` に限った（既定と同じだが、設計書どおりであることが読んで分かるよう明示）。2 回目以降のログインで名前・メールアドレスを更新するため `overrideUserInfoOnSignIn: true`。画面操作の中でログアウトしたときにクッキーを消せるよう `nextCookies()` を付けた。Better Auth のログは、このアプリのログの形（1 行の JSON・日本語の文言、元の英語は `detail`）で出す。
- 振り分け（`src/proxy.ts` と `modules/auth/route-guard.ts` の `decideRedirect`）: 判定は純粋関数にして、設計書「画面の振り分け」の表のすべての場合と、POST などを移さないことをテストした。proxy は Better Auth でログイン状態を確かめ、ログインしていれば `modules/household` の `hasMembership` で所属を DB から確かめる。API・画像・Next.js の内部のファイルは振り分けの対象外にした。
- モジュール: `modules/auth`（設定・ログイン中の人の取り出し・振り分けの判定・S01 の画面・ログアウト）と、`modules/household`（今回は所属の有無を調べるところだけ）。依存は household → auth の一方向（proxy は入口として両方を呼ぶ）。
- 画面: S01 ログイン（`/login`。背景画像・ロゴ・ボタン。失敗して戻ってきたら `?error=...` を見て設計書の文言を出す）。S02 は仮のページ（`/setup`）。設定の仮のページにログアウトのボタンを置いた。画像は `docs/mockups/` から `public/images/` へ写した。
- 環境変数: `.env.example` に `BETTER_AUTH_SECRET`・`BETTER_AUTH_URL`・`GOOGLE_CLIENT_ID`・`GOOGLE_CLIENT_SECRET` の名前と説明だけを書いた。Google Cloud の設定は [`Googleログインの準備.md`](../../development/Googleログインの準備.md) にまとめた。
- 確認: `pnpm lint` / `format:check` / `typecheck` / `test`（56 件）/ `build` が成功。ブラウザでログインしていない状態で `/settings` を開くと `/login` へ移ること、`?error=` 付きで文言が出ることを確かめた。ユーザーが `.env` に値を入れ、`pnpm dev` で実際に Google ログインし、初回設定の仮のページへ移ることを確かめた。

### 詰まったこと

- `BETTER_AUTH_SECRET` が無いと、`pnpm build` のときに「You are using the default secret」というエラーが表示される（ビルド自体は成功する）。本番（NODE_ENV=production）で秘密の値が無いと Better Auth が止まるための表示。CI にも秘密の値は置いていないので、同じ表示が出る。
- ログイン画面の背景の暗い帯は、画面イメージでは緑がかった色（`#14271ccc`）だったが、DESIGN.md で任意の色の値を禁じているため、Tailwind の標準の `black/70` で近い見た目にした。
